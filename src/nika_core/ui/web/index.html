Nika автоматично продовжує лише crash-left роботу з канонічно перевіреним checkpoint і без невизначених зовнішніх ефектів. Призупинена, очікуюча підтвердження або невизначена робота не запускається без відповідної authority.

Модель для нових завдань

Вибір зберігається до створення нового завдання і не змінює режим уже прийнятого завдання. Детермінований режим працює без LLM. Foundry Local використовує вбудовану локальну модель без мережевої адреси. Ollama використовує лише локальну адресу. Для API вкажіть лише посилання на змінну середовища у форматі env:НАЗВА; сам ключ у це поле не вводьте.

Наприклад: env:OPENAI_API_KEY. Не вводьте сюди API-ключ або пароль. Збережене посилання навмисно не показується після перечитування.

Для детермінованого та локальних режимів цей параметр не потребує зміни. Для зовнішнього API вмикайте лише коли політика постачальника це дозволяє.

Джерела команди

Виберіть папку та два різні файли для порівняння командою. Підтримуються TXT, MD, HTML, CSV, JSON, PDF, DOCX та XLSX, до 16 МіБ кожен. Нові налаштування застосовуються до нових завдань; розпочаті зберігають свої джерела.

Перевірка збережених налаштувань.

Голос Nika

Явно озвучує введений нижче текст локальним системним голосом Windows. Nika не читає результати, пам’ять або приватний вміст автоматично. Це системний голос Windows, а не фінальний власний голос Nika.

Перевірка локального озвучення.

Голосовий ввід

Запускає один явний локальний запис із мікрофона Windows, перевіряє голосову активність, локально розпізнає мовлення та перевіряє активацію Nika. Розпізнаний текст не створює завдання автоматично: спочатку перенесіть його в поле команди та перевірте перед окремим натисканням «Створити завдання».

Локальна модель розпізнавання

Якщо модель ще не встановлена, вкажіть повний шлях до локальної папки з encoder.onnx, decoder.onnx і tokens.txt. Nika копіює лише ці три файли у власну папку; мережа та автоматичне завантаження не використовуються.

Команда

Нове завдання незмінно фіксує вибрану модель разом з іншими налаштуваннями. Поточний контрольований сценарій команди зберігає власні детерміновані кроки; інтерфейс не підміняє runtime-стан або маршрут моделі.

Режим інтелекту можна перевірити командою «режим інтелекту» або змінити для нових завдань: «режим інтелекту deterministic», «режим інтелекту foundry <model>», «режим інтелекту ollama <model> <loopback-url>», «режим інтелекту api <provider> <model> <https-url> <env:REF> <public|private>». Уже прийняті завдання не перемикаються.

Для кількох завдань можна вибрати потрібне радіокнопкою у списку «Завдання» й скористатися кнопками керування вибраним завданням. Точні команди з task_id залишаються доступними: «pause task <task_id>», «resume task <task_id>», «stop task <task_id>» або «task status <task_id>». Українські відповідники: «призупини завдання <task_id>», «продовж завдання <task_id>», «зупини завдання <task_id>», «статус завдання <task_id>».

Якщо ProductProject очікує рішення власника, спочатку введіть «покажи поточне рішення ProductProject» або «show current product decision». Якщо очікують кілька рішень, команда «list pending product decisions» покаже до восьми decision_id на сторінку; наступні сторінки відкриваються командою «list pending product decisions page <номер>», а повне питання конкретного рішення — «show product decision <decision_id>». Щоб відхилити точно вибране рішення, введіть «reject product decision <decision_id>». Щоб схвалити його, введіть «approve product decision <decision_id>»: Nika покаже одноразовий approval request_id. Лише після окремої команди «confirm product decision approval <approval-request-id>» trusted host запише схвалення. Українські відповідники: «відхили рішення ProductProject <decision_id>», «схвали рішення ProductProject <decision_id>» і «підтвердь схвалення рішення ProductProject <approval-request-id>».

Для поточного ProductProject доступні точні команди Product Factory: «сплануй поточний ProductProject», «покажи поточний план Product Factory», «покажи поточний статус Product Factory» і «запусти поточний Product Factory». Перед запуском завантажте явний JSON-план у розділі ProductProject. Команда статусу лише читає перевірений durable execution state, не запускає воркерів і показує не більш як вісім компонентів за один раз.

        Локальний backend Product Factory

        Тут зберігається лише локальна host-конфігурація: абсолютний шлях робочої папки, дозволені виконувані файли та ресурсні межі. Локальні корені репозиторіїв мають окрему durable-прив’язку ProductProject і не приймаються цим JSON. Не вставляйте паролі, токени, API-ключі або інші секрети. Зміни backend застосовуються лише після перезапуску Nika.

        Перевірка збереженої конфігурації локального Product Factory.

        PF5 build runtime

        Тут зберігається host-owned PF5 authority: локальний execution node, ресурсні межі та дозволені build-команди для точних компонентів ProductProject. Candidate/план не може підмінити цю authority. Не вставляйте паролі, токени, API-ключі або інші секрети. Зміни застосовуються лише після перезапуску Nika.

        Перевірка збереженої конфігурації PF5 build runtime.

        План виконання Product Factory

        Вкажіть повний шлях до JSON-плану. Nika читає лише прямий звичайний файл, не зберігає шлях і не приймає секрети замість посилань на облікові дані.

        JSON-план виконання Product Factory ще не завантажено.

        Локальний репозиторій Product Factory

        Спочатку завантажте JSON-план. Виберіть репозиторій лише з цього плану та явно вкажіть повний шлях до його локального Git-кореня. Прив’язка надає Product Factory локальний доступ до цього репозиторію; зміна або скасування прив’язки під час виконання зупиняє нові ефекти. Шлях не показується у стані та журналі.
