# AI Trader — authorized accessible PAPER positions (Plan 5 §1)

This is a **read-only domain action** on the existing Core `ActionRegistry`/`Keymap`/`UIActionBridge`, the existing `PaperWorkspaceQuery`, and the shared Core permission callback/standing grant. It creates no broker, real-money trade, parallel runtime, scheduler, model authority, or permission store.

- Stable action ID: `trader.paper.positions.inspect`; scope: `trader.paper`; default unbound, user-remappable; text-first status messages work in Windows UIA and semantic Web.
- Trusted host installs `paper_positions_definition()` and `paper_positions_handler(query, host_scope=...)`. The host MUST resolve workspace/run and current Core permission from its authenticated identity on each invocation. Do **not** use the UI/model-provided scope or a `authorized` boolean.
- Command payload is empty or exact `{"page": integer}` only; page is 0-based, 0–10,000. No grants, credentials, account selection, external links, order placement or mutable permission fields can be supplied.
- Each page re-reads the canonical PAPER account, rechecks revocable Core permissions before and after read, and displays at most 10 fully validated position records, including venue timezone, instrument/currency, quantity, average price, and realized PnL.
- **Exact action-class isolation:** the host must construct `standing_paper_read_authorizer(..., action_id=PAPER_POSITIONS_INSPECT)` for the detailed position action. Its standing grant must have `action_class=trader.paper.positions.inspect`; a grant scoped only to `trader.paper.account.inspect` is insufficient. The authorizer defaults to the account-summary class for existing callers, rejects arbitrary/behavioral action IDs, and retains Core denial/revocation/restart semantics. No UI/model-supplied action class may control the trusted host resolver.
- Returns explicit authorized no-data / no-open-position states, denied, unavailable and invalid-page states. No silently fabricated balances. The 32 KiB response bound is fail-closed (never cuts off or misrepresents a position). Exceptions and rejected payload content are not echoed.
- `tests/test_plan5_trader_distinct_read_permissions.py` exercises the real SQLite-backed Core permission store: summary-only grant denial for detailed positions, separate-grant success, revoke/restart denial, summary compatibility, and unsupported action rejection.
- `tests/test_plan5_trader_paper_positions_action.py` covers the keyboard-remappable Core action, two-page navigation, cross-scope/real-money payload attacks, revocation between pages and during failure, corrupt position data, empty pages, and SQLite keymap restart.
