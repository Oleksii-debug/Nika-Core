# Автозапуск Nika у Windows

У зібраному Windows-застосунку відкрийте «Автозапуск Windows» через основну
навігацію. Перейдіть Tab до прапорця «Запускати Nika разом із Windows»,
змініть його клавішею Пробіл і натисніть «Зберегти автозапуск».
Сама зміна позначки ще не зберігає налаштування: це явно показано текстом.
Після відповіді програми фокус повертається до прапорця.

«Перечитати автозапуск» відкидає незбережену позначку та показує поточний
системний стан. Обидві команди мають сталі ідентифікатори
`settings.autostart.configure` і `settings.autostart.refresh`; комбінації
для них можна призначити в наявному розділі «Клавіатура».

## Що означає стан

- «Увімкнено» — системний запис точно відповідає поточному виконуваному файлу.
- «Вимкнено» — запис NikaCore відсутній.
- «Застарілий або інший запис» — шлях чи команда не відповідає поточному
  пакету. Після переміщення програми явно позначте прапорець і збережіть,
  щоб оновити запис, або зніміть позначку й збережіть, щоб прибрати його.
- Помилка читання чи підтвердження — успіх не припускається. Перечитайте
  стан перед повтором. Після розриву зв’язку запис міг уже відбутися;
  програма не повторює його автоматично.
- У запуску з Python або поза Windows функція недоступна; Python не
  реєструється замість програми.

Налаштування стосується лише поточного облікового запису Windows і не
потребує підвищення прав. Використовується наявний `WindowsAutostartService`
та єдиний запис `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\NikaCore`.
Запис містить тільки точний шлях поточного EXE з належним екрануванням;
інтерфейс не приймає довільної команди чи шляху для автозапуску.

Вхід у Windows, а не просто ввімкнення живлення, є системною подією запуску.
Windows може відкласти запуск; це не обіцянка негайної готовності програми.
Надмірно довгий шлях може перевищити системну межу команди Run.

## Дані, дозволи та відновлення

Автозапуск відкриває програму, але не надає дозволів виконувати чи повторювати
завдання. Він не створює другого механізму відновлення. Поточна черга,
ідемпотентність, перевірка збережених сесій та канонічне відновлення даних
залишаються відповідальними за подальші дії. Див. `V01_DATA_RECOVERY.md`.

Журнал містить лише запитану логічну позначку та факт її підтвердження.
Системні шляхи, сторонні команди й тексти низькорівневих помилок не
потрапляють у стан інтерфейсу або цей журнал. Помилка запису журналу до
системної зміни блокує зміну. Помилка після неї повертає непідтверджений
результат; нове читання показує фактичний системний стан.

## Повторне використання та перевірки

REUSE: інтегрований сервіс автозапуску, стандартний Windows Run API,
Action Registry/Keymap, AuditLog, pywebview/WebView2, семантичний HTML.
ADAPT: вузький командний і read-only адаптер у DesktopBackend.
CUSTOM(thin): лише Nika-специфічні стани, повідомлення, вибір користувача
та інтеграційні тести; нової бібліотеки або системного менеджера не потрібно.

Перевірені офіційні джерела:
[Microsoft Run/RunOnce](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys),
[W3C checkbox keyboard pattern](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/).

Автоматичні перевірки:

- `test_v01_autostart_settings.py`: точний EXE, строгий payload, відмова без
  запису, аудит, застарілий шлях, повторний виклик, перезапуск адаптера,
  відсутність побічного виконання завдань.
- `test_v01_autostart_ui.py`: справжній app.js, вибір і збереження,
  невдалі відповіді, відставання читання, відсутність автоматичного повтору,
  семантика клавіатури, фокус і безпечні повідомлення.
- `v01_autostart_uia_proof.ps1`: лише ізольований GitHub-hosted Windows
  runner; три окремі запуски того самого зібраного EXE через наявний
  суворий M5 UIA harness: увімкнення, спостереження після перезапуску,
  вимкнення. Перед тестом наявний запис забороняє мутацію. При аварії
  прибирається лише точний власний тестовий запис, інші значення не чіпаються.

Це не перевірка фактичного входу користувача у Windows, не дозвіл на
виконання цього мутаційного тесту на його ПК і не людська перевірка NVDA.
`HUMAN_TESTED=false`, `NVDA_VERIFIED=false` до відповідного реального доказу.
